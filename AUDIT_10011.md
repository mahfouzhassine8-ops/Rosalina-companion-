## Reproduced failure

Unmodified production Live startup on a small API-35 emulator failed in `Session.prepareLiveVoice`: `IllegalArgumentException: Live Voice needs more free RAM`. The warmup Deferred belonged directly to the outer task job; its failed child cancelled that job despite the intended task catch boundary. Baseline reproduction run 36494511730 captured the fatal exception. The ordinary Chat/Live tab-switch tests passed; without the user's phone stack this is not proof it was their only crash cause.

## Repairs

- Give Live warmup lexical structured-concurrency ownership and bounded startup, retain the actual memory rejection, cancel/join startup before releasing microphone/task ownership. Keep missing-model errors visible and retain engine quarantine.
- Coalesce rapid Live-start requests; Stop cancels queued startup. A saved Live pane no longer automatically warms Chat on resume. Manual interruption stays available during an active session.
- Keep approved avatar JPEG bytes unchanged. Use a local precomputed regular 2-D mesh for independent head/hair/shoulder motion, blink compression, and restrained voice-energy jaw movement. Cache decoding and drawing objects; pause the frame clock when hidden/backgrounded and respect system animation settings and thermal frame budgets.
- Append streaming text instead of replacing the whole growing TextView, batch draft persistence with navigation/lifecycle flushes, and decode preview images off the UI thread with cancellation/stale-view protection.
- Restore explicit Create/Edit/Animate routing from the Companion text composer, retain chosen-photo validation and the existing engine routes. General tool-planning or identity-preserving image editing is not claimed.
- Keep model registry memory publication after its atomic write. Cancel superseded photo imports without replacing the selected photo with stale work. Serialize gallery saves and remove incomplete pending entries on cancellation. Report absent open/share handlers instead of crashing.
- Wrap the compact header without deleting controls; add accessible navigation labels, drawer dismissal/back handling, and button feedback. Keep the dark/purple visual identity and destinations.
- Keep live diagnostic history bounded; capture private per-process fatal/nonfatal stacks and Android exit evidence on explicit diagnostics requests. No crash handler suppresses Android's fatal handler; no diagnostics are uploaded automatically.
- Fix speech-focus cleanup after denial, do not count intentional AudioTrack interruption as a write failure, and use generated sample count for audio-duration reporting. Avatar Speaking follows playback events, not model preparation.
- Report inaccessible CPU counters as unavailable, not 0% usage. The online-preference UI does not represent an implemented provider; new default is off, saved explicit preferences remain intact. No network or Mac execution provider is added.
