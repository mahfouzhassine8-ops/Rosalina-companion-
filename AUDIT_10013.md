# Rosalina 10013 — Chat + Live Focus C1

Base: locked 10012 commit `e7b7bba776be1c31c443424b627ff831f3a08373`.

## Product goal

Rosalina is now optimized around two primary experiences: powerful local text Chat and local Live Voice. Photo, Edit and Animate source/native engines remain preserved for rollback compatibility, but the focused UI and task router will not start them.

## Conversation focus

- Drawer/rail expose Companion and Settings & Models only.
- Legacy saved Photo/Animate section state migrates back to Companion on launch.
- Typed prompts always stay in Chat; image/edit/animate wording no longer diverts into render workers.
- Classic Voice and Live Voice transcripts always continue into Qwen conversation; they no longer launch media rendering.
- Session.begin explicitly refuses CREATE/EDIT/ANIMATE tasks in this focus candidate.
- Models UI exposes Chat, Whisper and Kokoro only. Existing image/video model files are left untouched on disk.

## Heat behavior

- The persistent foreground notification no longer displays thermal status or render work hints.
- Chat/Live are no longer app-stopped by the render thermal Safe Stop rule.
- Heavy-render thermal policy and native worker safety code remain preserved but unreachable from the focused app path.
- Diagnostics can still read Android thermal state on demand.
- The live avatar is capped to 20 fps normally, 15 fps at Moderate and 10 fps at Severe to reduce continuous display/CPU work.

## TTS / Live audio architecture

- SpeechService now runs in the main app process so microphone capture and speaker playback share one AudioManager route owner.
- Live conversation playback uses VOICE_COMMUNICATION semantics; text-chat/read-aloud uses MEDIA semantics.
- PCM output changed from float to universally supported 16-bit mono PCM.
- Communication mode/device is established explicitly for Live and restored only when SpeechService had to establish it itself.
- Existing headset/Bluetooth/speaker preference remains, with Android retaining final routing authority.
- Settings adds `Test Rosalina speaker`, which bypasses Qwen/Whisper and speaks a fixed local Kokoro sentence. This separates TTS/speaker acceptance from Live acceptance.
- Diagnostics record route, encoding, usage, audio mode and first-audio timing.

## Acceptance

CI can prove compilation, packaging, model/engine preservation, emulator behavior and logical routing. It cannot prove that the physical Samsung speaker is audible. Real-device acceptance requires:
1. Settings → Test Rosalina speaker is audible.
2. Text Chat still streams responses quickly and remains warm across turns.
3. Live hears the user, answers, speaks audibly, and can repeat multiple turns.
4. No thermal wording appears in the normal foreground notification.
5. Chat/Live are not terminated by Rosalina thermal Safe Stop logic.

Do not lock 10013 until those real-device checks pass.
