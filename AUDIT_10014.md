# Rosalina 10014 — Chat + Live Focus C2 / Phone Capability Repair

Base: 10013 Chat + Live Focus C1 on branch history; locked rollback remains 10012.

## Why this candidate exists

Real-device testing showed both text-chat read-aloud and Live remained silent on the Samsung phone. The common failure boundary is the shared TTS playback path. 10013 also moved SpeechService into the main process even though NativeRpcService intentionally kills its hosting process during shutdown/unbind; that lifecycle assumption only works when speech remains isolated.

## Audio repair

- Restore SpeechService to the isolated `:speech` process so speech cleanup cannot kill Rosalina main.
- Remove forced communication-device routing from speaker playback.
- Use Android `STREAM_MUSIC` with 16-bit mono PCM: the same normal media path used by ordinary Android audio apps.
- Check media stream volume/mute explicitly and surface a real error instead of silently accepting zero-volume playback.
- Emit playback-start while AudioTrack is actually playing, not after playback has already completed.
- Add a model-independent 440 Hz speaker-tone test to separate Android speaker-path failure from Kokoro failure.
- Keep a separate Kokoro voice test.
- Diagnostics include actual route, stream volume/max, mute state, PCM format and media usage.
- Temporarily keep natural voice pitch on the compatibility path; do not claim manual pitch is applied.

## Phone capability adaptation

Default mode is `Adaptive`.

- Adaptive Full: used with strong RAM headroom and low thermal pressure; chat cap 1280, live cap 384, full-duplex overlap enabled.
- Adaptive Balanced: used at Moderate heat or reduced RAM; chat cap 768, live cap 224, turn-duplex behavior to reduce simultaneous CPU/audio work.
- Adaptive Cool: used at Severe heat or low free RAM; chat cap 384, live cap 144, no proactive chat prewarm, turn-duplex behavior.
- User may explicitly choose Cool or Maximum in Settings.
- Thermal state changes conversation workload; it does not trigger the old render-style Chat/Live Safe Stop.
- Live warmup is staged Qwen -> Whisper -> Kokoro instead of warming all three engines concurrently.
- Avatar cadence remains phone-focused from the previous pass.

## Product scope

Chat and Live remain the active product surface. Photo/Edit/Animate code and model files remain preserved but unreachable from normal focused UI/task routing.

## Real-device acceptance order

1. Test phone speaker tone. If silent, the issue is Android media output/routing and Kokoro is not relevant yet.
2. Test Rosalina voice. If tone works but voice is silent/fails, the issue is Kokoro generation/DSP/playback handoff.
3. Test text Chat with Read replies aloud.
4. Test Live for several turns.
5. Confirm Adaptive mode remains usable without the old thermal Safe Stop notification behavior.

Do not lock 10014 until physical-device audio and Live acceptance pass.
